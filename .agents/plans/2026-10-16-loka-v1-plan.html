Why the foundation comes first

Archive, undo, restore and unloading all need to know which real tab is which Loka tab, every time, across restarts and windows. Today that link lives in the sidebar page’s memory and is rebuilt by URL. Building those features on it would mean writing them twice.

Moving the rules into the browser process is how Chrome builds tab groups, bookmarks and history. The sidebar renderer can crash or reload without losing anything, and the C++ side can refuse a tab in two places instead of trusting a JSON blob.

The alternative is to keep the JavaScript model and patch the holes: per-window active space, ids in session data, diffs instead of snapshots. It’s cheaper now, but the truth stays in a renderer and every new feature crosses the same message bridge.

Shape of the C++ side (files, classes, migration)
  • components/loka/core/: the pure model, using only //base, with its own small unit-test target that builds in minutes. Today’s sidebar.test.ts cases become shared JSON fixtures that both the C++ and the TypeScript model must pass.
  • LokaSpacesService, one KeyedService per profile: owns the model, watches every window’s tab strip, keys tabs by TabHandle (it survives discards; the WebContents pointer doesn’t), and writes a Loka id per tab with SessionService::AddTabExtraData.
  • Saving: Loka Spaces.json in the profile through ImportantFileWriter, which batches writes and writes atomically.
  • A loka_sidebar.mojom interface. The page sends intents (ActivateTab, MoveItem); the service sends changes. Favicons go as chrome://favicon2 URLs, not inline PNGs.
  • Per-window state (active space) is saved with AddWindowExtraData.
  • Migration: the first run reads the loka.store pref into the new file and leaves the pref for one release, so rolling back an alpha loses nothing.
  • The TypeScript model stays only as the prototype’s stand-in backend, held equal to C++ by the shared fixtures.
Smaller calls I’ll make unless you object
  • Ctrl+W on a pinned tab resets it to its pinned URL and unloads it, as Zen does.
  • Tabs you close by hand go to the archive, which gives Ctrl+Shift+T and undo.
  • The archive keeps 30 days or 1,000 tabs, each with its Back history. Clear asks first.
  • Deleting a space archives its tabs instead of deleting them.
  • Memory Saver still discards live tabs; pinned rows don’t opt out of it.
  • Theme: build two calm skies in the prototype, light from the lab’s “Mist” and dark from “Eclipse”, and you pick one before the native change.
Risks, from assuming v1 shipped and failed
  • C++ work stalls on build times. The model stays in a //base-only component with its own tests, and UI work stays in TypeScript.
  • A Helium merge breaks the riskiest patches mid-v1. Patch cleanup runs before phase 2 lands.
  • Restoring hundreds of tabs is slow at startup. Unloaded pinned tabs restore as rows, not tabs, and phase 1 measures this.
  • Two models drift (C++ and the prototype). The shared fixtures fail CI when they disagree.
  • Arc found only 5.5% of daily users kept more than one space. One space with pinned tabs and an archive has to feel good alone.
